04.基于github的个人博客搭建教程

发表于2026-06-03|更新于2026-10-14|技术教程
|总字数:2.1k|阅读时长:7分钟|浏览量:

这篇文章以 Windows PowerShell 为例，记录从本地创建 Hexo 站点到发布到 GitHub Pages 的流程。命令和界面会随 Hexo、GitHub 的版本变化，开始前先确认本机已安装 Node.js 和 Git。

0.前置条件

在安装 Hexo 之前，需要先安装 Git 和 Node.js。安装后重新打开 PowerShell，确认 git --version 和 node --version 能输出版本号。

1.安装hexo

Hexo 是一个使用 Node.js 的静态博客框架：文章用 Markdown 编写，生成后成为可部署的静态网页。

4. 编写和发布文章

(1) 新建文章

文章会创建在 source/_posts/文章标题.md

(2) 编辑文章

用 Markdown 编辑器（推荐 Typora 或 VS Code）打开 .md 文件，你会看到：

  • 在 tags: 后面可以添加标签，如：tags: [网络安全, 学习笔记]
  • 在 --- 下方写正文内容（使用 Markdown 语法）
  • 可以在正文中插入 <!-- more -->，实现首页摘要显示

给文章添加图片

图片文件名尽量用英文、数字和连字符，并给图片写有意义的替代文本。保存后在项目根目录运行 npm run build，或执行 npx hexo generate；生成结果应包含 public/img/posts/docker/container-flow.webp。再运行 npx hexo server 打开文章预览，确认图片显示后执行 npx hexo deploy，图片就会和网页一起上传，访客浏览文章时也能看到。

上传前先压缩过大的图片，并确认自己有权公开使用图片。GitHub Pages 会像提供其他静态网页文件一样提供已部署的图片文件。

不要把图片只放进 public：public 是生成目录，清理或重新生成时会被覆盖。更完整的图片目录方案见 Hexo 图片资源目录文档。

5. 常用命令速查

命令 说明
npx hexo new "文章名" 新建文章
npx hexo clean 清除缓存和生成目录
npx hexo generate 生成静态网页
npx hexo server 本地预览（http://localhost:4000）
npx hexo deploy 部署到 GitHub
npx hexo version 查看 Hexo 版本

6. 常见问题解决

问题1：部署时提示 Permission denied (publickey)

解决方法： 先运行 ssh -T git@github.com，确认 GitHub 账号中添加了对应的 .pub 公钥；检查 SSH 客户端是否能找到私钥，再重新部署。不要公开或复制私钥内容。

问题2：访问博客显示 404

解决方法： 确认用户站点仓库名是 用户名.github.io，并在 Settings → Pages 检查发布来源、分支和目录；再查看 Pages/Actions 部署是否成功。

解决方法： 打开浏览器开发者工具检查 CSS 请求是否 404；确认 _config.yml 里的 url 和 root 与部署路径一致，再重新生成并部署。确认为生成缓存异常时才运行 npx hexo clean。

7. 进阶：更换主题

Hexo 默认主题比较简陋，可以更换更美观的主题。推荐主题：

  • Butterfly：功能最全、最华丽
  • NexT：经典、简洁、优雅
  • Fluid：现代化、高颜值

8. 总结

Hexo 的发布流程是：在 source 中维护文章和图片，用 hexo generate 生成 public，本地预览确认后再部署。博客源文件要单独备份；部署目录只负责提供浏览器访问的静态页面。祝你写作顺利喵。
