04.基于github的个人博客搭建教程

发表于2026-06-03|更新于2026-10-17|技术教程
|总字数:4.7k|阅读时长:16分钟|浏览量:

这篇文章以 Windows PowerShell 为例，记录从本地创建 Hexo 站点到发布到 GitHub Pages 的流程。命令和界面会随 Hexo、GitHub 的版本变化，开始前先确认本机已安装 Node.js 和 Git。

0.前置条件

在安装 Hexo 之前，需要先安装 Git 和 Node.js。安装后重新打开 PowerShell，确认 git --version 和 node --version 能输出版本号。

1.安装hexo

Hexo 是一个使用 Node.js 的静态博客框架：文章用 Markdown 编写，生成后成为可部署的静态网页。

上传前先压缩过大的图片，并确认自己有权公开使用图片。GitHub Pages 会像提供其他静态网页文件一样提供已部署的图片文件。

不要把图片只放进 public：public 是生成目录，清理或重新生成时会被覆盖。更完整的图片目录方案见 Hexo 图片资源目录文档。

5. 常用命令速查

命令 说明
npx hexo new "文章名" 新建文章
npx hexo clean 清除缓存和生成目录
npx hexo generate 生成静态网页
npx hexo server 本地预览（http://localhost:4000）
npx hexo deploy 部署到 GitHub
npx hexo version 查看 Hexo 版本

6. 常见问题解决

问题1：部署时提示 Permission denied (publickey)

解决方法： 先运行 ssh -T git@github.com，确认 GitHub 账号中添加了对应的 .pub 公钥；检查 SSH 客户端是否能找到私钥，再重新部署。不要公开或复制私钥内容。

问题2：访问博客显示 404

解决方法： 确认用户站点仓库名是 用户名.github.io，并在 Settings → Pages 检查发布来源、分支和目录；再查看 Pages/Actions 部署是否成功。

问题3：文章发布时间差8小时

原因： 时区设置问题

解决方法： 在 _config.yml 中设置：

问题4：本地预览正常，但部署后样式丢失

解决方法： 打开浏览器开发者工具检查 CSS 请求是否 404；确认 _config.yml 里的 url 和 root 与部署路径一致，再重新生成并部署。确认为生成缓存异常时才运行 npx hexo clean。

7. 配置 Butterfly 主题

本博客使用 Butterfly 主题。Hexo 根目录的 _config.yml 管理站点地址、生成器和部署方式；Butterfly 的显示选项放在 Hexo 根目录的 _config.butterfly.yml。两份文件用途不同，不要把主题设置误写进 Hexo 的配置文件。

7.1 启用主题并分开放置配置

在 Hexo 根目录的 _config.yml 中选择主题：

Butterfly 自带的默认配置位于 themes/butterfly/_config.yml。在项目根目录单独维护 _config.butterfly.yml，可以覆盖主题默认值，也能降低升级主题时覆盖个人配置的风险。不要删除主题自己的默认配置文件。

Butterfly 快速开始文档说明了主题选择和独立配置文件的合并规则；升级时仍要查看对应版本的更新说明，因为主题版本可能新增、弃用或调整配置项。

7.2 菜单、站点信息和侧栏

菜单标题、链接和图标写在 _config.butterfly.yml 的 menu 下。|| 后面是 Font Awesome 图标类名：

菜单链接要与实际生成的页面路径一致。比如把链接写成 /tags/，就要有标签页面；页面空白时，应同时检查页面文件、Front-matter 类型和生成结果。

站点名称、作者、简介、域名和 root 路径位于 Hexo 根目录的 _config.yml。Butterfly 的 aside 配置负责侧栏：可以单独启用作者卡片、公告、最新文章、分类、标签和归档卡片。GitHub 按钮的地址也应填写自己的真实主页地址。卡片是否显示由对应的 enable 控制，不需要的卡片可以关闭。

Butterfly 的 background 控制全站背景，index_img 设置首页顶部图。颜色值建议使用引号，避免 YAML 把特殊字符解析成其他类型：

图片放在 Hexo 项目的 source 中，例如 source/img/bg.jpg；发布时 Hexo 会把它复制到 public/img/bg.jpg，网页再通过 /img/bg.jpg 引用。不要把个人图片放进 themes/butterfly/source，主题升级时该目录内容可能被覆盖。也不要只把文件放在 public，因为它是生成目录，重新生成时会被清理或覆盖。

脚本把导航、搜索提示、按钮和部分卡片文字映射为英文或中文，并记住访客选择。它不是自动翻译器，不会翻译 Markdown 文章内容；新增界面文案时，要在映射表里补上对应词条。若换了 Butterfly 版本或修改了右下角按钮结构，也要确认脚本仍能找到插入按钮的位置。

8.3 加入 Live2D 看板娘

看板娘由自定义加载脚本和模型文件组成。本博客的加载器位于 source/js/live2d-widget-v3.js，模型资源放在 source/Resources/，发布后对应 /Resources/ 路径。Butterfly 通过 inject.bottom 加载该脚本：

当前脚本从 jsDelivr 加载 Live2D SDK、样式和提示语文件，模型资源则从博客自己的 /Resources/ 读取。它只在 screen.width >= 768 时初始化，因此手机屏幕不会加载看板娘。若改为项目子路径部署，模型和脚本路径也要随 Hexo 的 root 调整。

模型能否显示，取决于模型配置引用的文件是否齐全、文件名大小写是否一致，以及浏览器是否成功下载 SDK 和模型资源。动作和表情也不是只添加一个工具栏按钮就会自动生成：动作、表情资源必须存在，并由模型配置正确引用。模型无法移动或动作无响应时，先检查开发者工具的 Console 和 Network，确认 model3.json、动作文件、表情文件和纹理没有 404，再检查模型配置中的资源名称。

头像图片应放在 source/img/friends/，例如 source/img/friends/example.jpg 对应网页路径 /img/friends/example.jpg。编辑 YAML 时要注意缩进；如果卡片没出现，依次确认 type: link、数据文件路径、link_list 结构和图片是否进入生成目录。

8.6 关闭评论和检查发布结果

如果博客不提供评论，在 _config.butterfly.yml 中将 comments.use 留空即可全站关闭。不要把它写成 []：空数组在 JavaScript 中仍是真值，部分主题模板会因此保留评论容器。若只想关闭某个独立页面，可在该页面 Front-matter 中设置 comments: false。

配置完成后，建议按这个顺序检查：

  1. 运行 npm run build，确认生成过程没有模板或 YAML 错误。
  2. 运行 npm run server，检查首页、文章、搜索、友链、404、日间和夜间样式。
  3. 用浏览器开发者工具检查缺失图片、脚本或样式对应的 404 请求。
  4. 确认无误后运行 npm run deploy，再打开线上页面检查一次。

自定义 CSS 和 JavaScript 都会进入公开网页。不要在其中写入访问令牌、私钥或其他服务端秘密；需要保密的数据不能放进静态站点。

9. 总结

Hexo 项目的主要内容位于 source，站点配置位于根目录的 _config.yml，Butterfly 的主题配置位于 _config.butterfly.yml。生成命令把源文件转换到 public，本地预览确认页面和资源路径正确后，再部署生成结果。主题功能可以逐项添加，但每多一个脚本或外部资源，就多一项需要维护的依赖；保留必要功能，并在主题升级后复查相关配置。

以上步骤都完成后，博客就发布成功了喵。
